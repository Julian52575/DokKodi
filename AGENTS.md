# Agent instructions

DokKodi is one repository with two apps: `desktop/`, a native desktop app
(Tauri 2: React + Vite + Tailwind frontend, Rust backend), and `mobile/`, an
Android app (Expo / React Native + NativeWind).

Read [README.md](README.md) and [CONTRIBUTING.md](CONTRIBUTING.md) before
changing anything; they are the source of truth. The hard rules:

- **Conventional Commits** for every commit and PR title:
  `<type>[(scope)][!]: description`, lower-case subject, no trailing period.
  Useful scopes: `desktop`, `mobile`, `ci`, `nix`.
- **Signed, signed-off commits**: `git commit -s` with signing configured;
  the `commit-msg` hook rejects anything else.
- **Link the issue** a PR resolves (`Closes #NNN` in the body). Branch from `main`;
  never push to `main`.
- **Workflows** (`.github/`):
  - pin every action to a full commit SHA with a `# vX.Y.Z` comment that
    matches it (`pin-github-action` does this);
  - least-privilege `permissions:` at workflow level, widened per job only
    where needed;
  - `timeout-minutes` on every job, `step-security/harden-runner` as each
    job's first step, `persist-credentials: false` on every checkout;
  - never expand `${{ … }}` inside `run:` — pass it through `env:`;
  - make a new job mandatory by adding it to `ci-required.needs` in
    `ci.yml`, never by editing `.github/rulesets/main.json`.
  - Run `just lint-workflows` (actionlint, zizmor, schema) before committing.
- **Tooling** comes from the Nix dev shell (`nix develop`).
- **Always pin the latest prebuilt binary release; never rely on nixpkgs
  and never compile.** `nix develop` must only download. A tool goes in its
  own `nix/<tool>.nix`, listed in `nix/tools.nix`, pinned to the **latest
  release** that upstream publishes as a prebuilt binary (Node.js, Rust, the
  Temurin JDK, the Android command-line tools, just, jq, …), with a hash per
  platform and a comment saying how to bump it. Fall back, in this order, to
  an official package (a PyPI wheel), then to the newest build on
  `cache.nixos.org` (nixpkgs-unstable) with its version asserted, and only
  when upstream ships no binary at all. Never override a nixpkgs package's
  source: that compiles on every machine. The only things taken from
  nixpkgs directly are libraries with no upstream binary (the Tauri Linux
  libraries) and the compiler wrapper from `mkShell`.
- **Lockfiles** (`desktop/package-lock.json`, `mobile/package-lock.json`,
  `desktop/src-tauri/Cargo.lock`) are committed; CI installs with `npm ci`.
- **No OS-specific scripts**: helper scripts are Python 3 (standard library
  only), not shell, so they run on Linux, macOS and Windows. `justfile`
  recipes stay one-liners.
- **Secrets** never go in git. New variables go in `.env.example` with a safe
  placeholder; `change-me-*` values are generated by the shell.
- **Comments** stay short and explain why, not what.
- Record incidents and their fixes under `docs/troubleshooting/<area>/`
  (see CONTRIBUTING.md).
- AI-assisted commits carry a `Co-Authored-By:` trailer naming the assistant.
